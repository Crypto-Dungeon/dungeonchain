# Dungeon v13.1.1 — contract roles + transaction fees are charged

**Install v13.1.1, not v13.0.2, for governance proposal 45.** Proposal 45 schedules
plan **`v13-contract-roles`** at height **22500000**. Its on-chain plan info still
links the v13.0.2 binary; do not use that link or Cosmovisor auto-download for this
upgrade. Stage v13.1.1 by hand. Keep v13.0.1 running until the height. Do not roll
back or replay the v13.0.1 recovery.

v13.1.1 and v13.0.2 make the same contract-role change, but from this height v13.1.1
also charges transaction fees. A node that runs v13.0.2 here computes different
results on the first transaction that pays a fee, stops with an app-hash error, and
must switch to v13.1.1. If more than a third of voting power runs v13.0.2, the chain
stalls until enough validators switch.

## 1. Transaction fees are debited

From v6 through v13.0.1 the ante chain compared a transaction's declared fee to the
globalfee minimum (0.01 udgn per gas) but never deducted it, so fee_collector never
received fees. From height 22500000, `ante.NewDeductFeeDecorator` runs right after
the globalfee check: the declared fee is debited from the fee payer (or the fee
granter) and goes to fee_collector, then to validators and delegators through
distribution. A fee larger than the payer's balance fails with "insufficient funds".

The fee-exempt signers (admin/treasury and the btc-relayer) are unchanged: they
still skip both the minimum check and the deduction.

**Operators who sign transactions on dungeon-1 (relayers, bots) must hold DGN for
fees before the upgrade height.** Typical fees are 0.01–0.5 DGN per transaction.

## 2. Five remaining contract control roles

Unchanged from v13.0.2. One internal config role in each contract moves to the
recovery address `dungeon10cr0mweqjyz856kyyy03yzj6av3vmy0p0653lh`:

| Contract | Code ID | Role |
| --- | ---: | --- |
| Active AMM Pool Factory | 160 | owner |
| Dungeon Games Pool Factory v2 | 19 | owner |
| Dungeon Fantasy Sports | 74 | admin |
| castle-siege-v3 | 220 | admin |
| castle-siege-e2e-test | 208 | admin |

The handler pins every address, code ID and hash, migration administrator and
source-config hash, changes only the role bytes, and applies all five atomically.
A mismatch at the upgrade height halts the upgrade for review.

## Validation

- New tests: a normal fee is charged and reaches fee_collector; a fee above the
  balance is rejected and nothing moves; an exempt signer is not charged; the
  binary registers `v13-contract-roles` and no other new plan. The fee tests fail
  with the deduction removed.
- Full `go test ./...` passes; the mainnet-state role rehearsal passes.

Check the archive against **ASSET-SHA256SUMS**, then `dungeond`, `version.txt` and
`provenance.txt` against **SHA256SUMS**. `dungeond version --long` must report
**13.1.1**; `provenance.txt` must report plan **v13-contract-roles** and `dirty=false`.

## Activation

1. Stage the verified binary at `cosmovisor/upgrades/v13-contract-roles/bin/dungeond`
   (replace any v13.0.2 already there).
2. Make sure signing accounts hold DGN for fees.
3. At 22500000 the node halts on v13.0.1 and Cosmovisor starts v13.1.1.
4. After the upgrade: confirm the five roles, and that a fresh transaction's fee
   reached fee_collector.
