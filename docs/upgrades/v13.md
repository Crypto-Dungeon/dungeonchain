# Dungeon v13 — coordinated restart after the 2026-10-25 key theft

dungeon-1 stopped producing blocks at height **22368768** (2026-10-26 11:02:17 UTC).
v13 is a **height fork**, not a governance upgrade: there is no proposal. Every
validator replaces the v12 binary with v13 and starts again. v13 applies the
recovery in BeginBlock of **22368769**, the first new block.

The chain resumes once more than 2/3 of voting power is running v13.

## What v13 changes at 22368769

On 2026-10-25 an intruder stole the Crypto Dungeon operations key and the keys
of three Crypto Dungeon validators. v13:

1. Returns the stolen DGN. The thief's 31,949,067.86 DGN and the operations
   wallet's 10,085,802 DGN of unbonding go to the new operations address
   `dungeon10cr0mweqjyz856kyyy03yzj6av3vmy0p0653lh`.
2. Rotates the consensus keys of The Hive, CryptoDungeon and House of the Holy.
   This uses the SDK's own `MsgRotateConsPubKey` path, which takes effect at
   22368771.
3. Freezes five addresses: the old operations wallet, the thief's address, and
   the three operator accounts. The ante handler refuses any transaction they
   sign, pay fees for or authorize. The three operator accounts' liquid balance
   and commission move to the new operations address.
4. Moves the old key's remaining contract roles (three cw721 collections and
   three CLOBs) to the new operations address.
5. Recovers the DRAGUU DAO's bootstrap stake and installs fresh governance
   modules. See `v13-draguu-recovery.md`.
6. Closes the DGN warp route to Base until it has new keys.

No other account, balance, delegation or parameter changes.

## Steps for validators

```sh
# 1. stop the node
sudo systemctl stop <your dungeond / cosmovisor service>

# 2. install v13 where cosmovisor's current binary is
#    (current -> upgrades/v12 on most nodes; keep a copy of v12)
cd "$DAEMON_HOME/cosmovisor/current/bin"
cp dungeond dungeond.v12.bak
tar -xzf dungeonchain-13.0.0-linux-amd64.tar.gz dungeond
sha256sum dungeond            # must match SHA256SUMS in the release
./dungeond version --long     # version 13.0.0, commit as in the release

# 3. start again. No reset, no rollback, no config change.
sudo systemctl start <service>
```

- **Don't start on v12.** A v12 node computes a different result at 22368769
  and can't follow the chain.
- **Don't run `unsafe-reset-all` or `rollback`.** Your data at 22368768 is correct.
- To build from source instead: check out tag `v13.0.0` and run
  `VERSION=13.0.0 bash scripts/build_v12_release.sh` on Linux amd64 with
  musl-tools 1.2.3+ and gcc-11. The script is unchanged from v12.

## Verify after restart

- Height 22368769 committed, with signatures from more than 2/3 of power.
- `dungeond q bank balances dungeon1q5sp3sl6h4kmgpt6ttrelrfgs07zsew039gs0f` is empty.
- At 22368771 and after, the three rotated validators sign with their new keys.

## Testing

`TestV13ForkOnMainnetState` runs the fork block and the two after it on a
disposable copy of the halted mainnet database (state at 22368768). It checks
every item above, and the full `./app/...` suite passes. See
`v13-draguu-recovery.md` for how to run it.
