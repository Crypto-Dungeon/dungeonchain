# Dungeon v13.1.0 — contract roles + transaction fees are charged

**Supersedes v13.0.2.** Do not stage the v13.0.2 binary. Keep v13.1.0 out of
Cosmovisor until the approved upgrade instructions and height are confirmed, and
keep v13.0.1 running until then. Do not roll back or replay the v13.0.1 recovery.

This release adds the scheduled software-upgrade handler **`v13.1`**. It is the
only new plan: the `v13-contract-roles` name from v13.0.2 is not registered, so a
node that still holds the v13.0.2 binary halts at the `v13.1` height instead of
running on with different consensus rules. Installing this binary does nothing by
itself; governance must approve a plan named exactly `v13.1` at an agreed height.

## 1. Transaction fees are debited

From v6 through v13.0.1 the ante chain compared a transaction's declared fee to the
globalfee minimum (0.01 udgn per gas) but never deducted it, so fee_collector never
received fees. From the `v13.1` height, `ante.NewDeductFeeDecorator` runs right
after the globalfee check: the declared fee is debited from the fee payer (or the
fee granter) and goes to fee_collector, then to validators and delegators through
distribution. A fee larger than the payer's balance fails with "insufficient funds".

The fee-exempt signers (admin/treasury and the btc-relayer) are unchanged: they
still skip both the minimum check and the deduction.

**Operators who sign transactions on dungeon-1 (relayers, bots) must hold DGN for
fees before the upgrade height.** Typical fees are 0.01–0.5 DGN per transaction.

## 2. Five remaining contract control roles

Unchanged from v13.0.2 (only the plan name differs). One internal config role in
each contract moves to the recovery address
`dungeon10cr0mweqjyz856kyyy03yzj6av3vmy0p0653lh`:

| Contract | Code ID | Role |
| --- | ---: | --- |
| Active AMM Pool Factory | 160 | owner |
| Dungeon Games Pool Factory v2 | 19 | owner |
| Dungeon Fantasy Sports | 74 | admin |
| castle-siege-v3 | 220 | admin |
| castle-siege-e2e-test | 208 | admin |

The handler pins every address, code ID and hash, migration administrator and
source-config hash, changes only the role bytes, and applies all five atomically.
A mismatch at the upgrade height halts the upgrade for review. Recheck the pinned
live state before proposal submission and again before activation.

## Validation

- New tests: a normal fee is charged and reaches fee_collector; a fee above the
  balance is rejected and nothing moves; an exempt signer is not charged; the
  binary registers `v13.1` and not `v13-contract-roles` or `v14`. The fee tests
  fail with the deduction removed.
- Full `go test ./...` passes. The v13.0.2 role-recovery tests run unchanged
  against the new plan name.

Check the archive against **ASSET-SHA256SUMS**, then `dungeond`, `version.txt`
and `provenance.txt` against **SHA256SUMS**. `dungeond version --long` must report
**13.1.0**; `provenance.txt` must report plan **v13.1** and `dirty=false`.

## Coordination and activation

1. Agree a future block height with validators.
2. Make sure the IBC relayers that sign on dungeon-1 hold DGN for fees.
3. Publish the release assets and finalize the proposal (source, checksum,
   download information, height). Recheck live governance parameters first.
4. Validators stage the verified binary for the Cosmovisor upgrade name **v13.1**.
5. After the upgrade: confirm the five roles, and that a fresh transaction's fee
   reached fee_collector.
