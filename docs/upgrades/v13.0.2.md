# Dungeon v13.0.2 — five remaining contract control roles

**Prepared final release. Activation height is not agreed and no upgrade proposal
has been submitted. Keep v13.0.1 running until the approved upgrade instructions
and height are confirmed. Do not roll back or replay the v13.0.1 recovery.**

This release adds the scheduled software-upgrade handler **`v13-contract-roles`**.
There is no new automatic height fork. Installing/building this release alone
does not perform the five-contract correction. Governance must approve a plan
with this exact name at an agreed future block height.

## Scope

The proposed correction transfers exactly one internal config role in each of:

| Contract | Code ID | Role |
| --- | ---: | --- |
| Active AMM Pool Factory | 160 | owner |
| Dungeon Games Pool Factory v2 | 19 | owner |
| Dungeon Fantasy Sports | 74 | admin |
| castle-siege-v3 | 220 | admin |
| castle-siege-e2e-test | 208 | admin |

The destination is the existing recovery address
`dungeon10cr0mweqjyz856kyyy03yzj6av3vmy0p0653lh`.
Reviewed implementation: [PR #31](https://github.com/Crypto-Dungeon/dungeonchain/pull/31).

This is an explicit consensus-state correction of five config strings, required
because Fantasy is immutable and has no admin setter. It does not add a Wasm
migration administrator to Fantasy. Contract code, migration administrators,
balances, other config fields, game progress, pool toggles, frozen-signer rules,
validator keys, bridge pauses and governance parameters are preserved.

The implementation pins all five addresses, code IDs and hashes, migration
administrators, and complete source-config hashes. It changes only the role
bytes, verifies the smart queries, and applies the corrections atomically. A
mismatch fails without applying any of the five changes. Such a mismatch at the
upgrade height halts the upgrade for review; operators must recheck the pinned
live state before proposal submission and again before activation.

## Validation and release integrity

- The executable app/cmd/dependency source is identical to the reviewed PR #31
  candidate source `e0df5abbdaa8bab5f6f2f0ae5bdc410b7aa27dfe`.
- A disposable mainnet-state rehearsal verified all five role changes, unchanged
  balances/other config/metadata, late-failure rollback, idempotence, and plan guards.
- App tests and the basic, IBC, CosmWasm and token-factory integration jobs passed.
- The final static Linux amd64 binary is built on a clean GitHub-hosted runner,
  using the existing release builder and hash-verified WasmVM 3.0.8 archive.
- The release build verifies static linking, binary version/provenance, clean
  tagged source, and the WasmVM version. `VALIDATION.txt` records its app tests.

Check the downloaded archive against **ASSET-SHA256SUMS**, then check the
extracted `dungeond`, `version.txt` and `provenance.txt` against **SHA256SUMS**.
`dungeond version --long` must report version **13.0.2** and the release tag's
source commit. `provenance.txt` must report plan **v13-contract-roles** and
`dirty=false`. The checksum of the earlier 13.0.2-rc.1 candidate is not the final
release checksum.

## Coordination and activation

1. Agree a future block height with validators and refresh the timing against the
   current chain and voting period. The earlier draft height **22500000** is
   tentative and is not a schedule or authorization.
2. Publish/approve the final release assets and finalize the proposal's source,
   binary checksum, download information and activation height.
3. Submit the governance proposal only after that coordination. Current observed
   expedited parameters are 48-hour voting with a 1,000,000 DGN initial deposit;
   recheck the live parameters before submission.
4. Validators should stage the verified binary for the exact Cosmovisor upgrade
   name **v13-contract-roles**, following the agreed runbook. Do not replace the
   current binary or restart early based on this draft release.
5. After the approved upgrade executes, query all five roles and confirm the
   recovery address, preserved migration admins/balances/config, and frozen old key.

No private key is required to apply this correction at the approved upgrade
height. The wBTC breaker's compromised default signer is a separate operational
follow-up. This release does not lock/unlock pools or configure automated signers.
